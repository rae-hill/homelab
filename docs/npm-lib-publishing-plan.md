# NPM Library Publishing Plan v2 (`lib/*` → `@rae-hill/*`)

Status: **implemented** (Nov 2026) — validated locally (build/docs/pack/MSR dry-run/Nix builds;
see "As-built corrections" at the bottom). Remaining: owner bootstrap steps (Trusted Publisher
config + baseline tag + first `feat(scratch):` push). Supersedes v1 (which assumed
`publishConfig.directory` + npm publish + NPM_TOKEN; research killed all three assumptions).

Publish ESM-only TypeScript libraries from `lib/` to npm under `@rae-hill`, with:

- **semantic-release** (conventional commits) choosing per-library versions, via
  `@anolilab/multi-semantic-release` (the only actively maintained monorepo runner, Nov 2026)
- **npm Trusted Publishing** (OIDC from GitHub Actions — **no npm token exists anywhere**)
- **provenance** generated by yarn itself at publish (sigstore bundle attached)
- **RsLib** builds (bundleless ESM + d.ts), **TypeDoc → committed markdown versioned by minor**,
  **RsPress v2** rendering gitignored HTML with a version dropdown
- first version **0.1.0**, so `^0.1.x` consumers are protected from minor (= API-change) releases

`packages/*` remains private app territory and is never published.

## Source-verified facts (why this design)

All verified Nov 2026 against primary sources; re-verify if versions move.

1. **Yarn berry applies `publishConfig` manifest overrides at pack time.**
   `packages/plugin-pack/sources/index.ts` (`beforeWorkspacePacking` hook) copies
   `publishConfig.{type,main,browser,module,exports,imports,bin}` (plus `types`/`typings` via
   `plugin-typescript`) verbatim into the packed manifest. → We can keep dev-DX
   `exports: { ".": { "import": "./src/index.ts" } }` in the root manifest and publish
   `exports → dist` via `publishConfig.exports`. **This is the keystone of the design.**
2. **npm does NOT do this** — `npm/cli/lib/commands/publish.js` flattens `publishConfig` into
   registry-side config only (tag/access/registry); no manifest field overrides. So npm-based
   publishing would require the messy dist-manifest copy step. Rejected.
3. **`publishConfig.directory` is not honored by berry** (yarnpkg/berry#705, still open) — packing
   always uses the workspace root. Fine: we ship `files: ["dist"]` from the root instead.
4. **Berry rewrites `workspace:` protocol deps in the packed manifest**: `workspace:*` → exact
   version, `workspace:^` → `^version`, `workspace:~` → `~version`
   (`plugin-pack/sources/index.ts`). → lib→lib deps use `workspace:^`; no manual
   version-resolution script needed (the old-job copy-and-rewrite step is obsolete).
5. **`yarn npm publish` supports OIDC trusted publishing** (berry ≥ 4.10, PR #6898): auto-detects
   `CI=true` + `GITHUB_ACTIONS` + `ACTIONS_ID_TOKEN_REQUEST_{URL,TOKEN}`, exchanges an
   `npm:<registry-host>` audience token (`plugin-npm/sources/npmHttpUtils.ts#getOidcToken`).
   No `YARN_NPM_AUTH_TOKEN` needed in CI.
6. **`yarn npm publish` generates provenance itself** (berry ≥ 4.9, PR #6750):
   `plugin-npm/sources/npmPublishUtils.ts` builds a sigstore bundle (`sigstore.attest`) and
   attaches `{name}-{version}.sigstore` to the publish payload. Precedence: `--provenance` flag >
   `--no-provenance` > `publishConfig.provenance` > `npmPublishProvenance` setting. We set
   `publishConfig.provenance: true` per lib. Other useful flags: `--access`, `--tag`,
   `--tolerate-republish`, `--dry-run`, `--staged`.
7. **npm Trusted Publishing** (docs.npmjs.com/trusted-publishers): requires npm CLI ≥ 11.5.1 +
   Node ≥ 22.14 (runner has Node 26 ✓); configured on npmjs.com with owner/repo/**exact workflow
   filename**; can be configured at **scope level (`@rae-hill`) before any package exists** — one
   setup covers all future libs (verify in UI at bootstrap); the first successful publish must land
   within **2 days** of creating the config or it expires. Provenance is expected/automatic in this
   flow. `id-token: write` is the only credential.
8. **`@semantic-release/npm` v13+** supports OIDC natively (v13.1.0: verify via dry-run publish +
   id-token bearer instead of `npm whoami`; issue #958). We still set `npmPublish: false` because
   publishing goes through `yarn npm publish` (facts 4–6); the plugin is used **only to bump the
   version** in `package.json` during `prepare`.
9. **Berry lockfiles don't record workspace versions** (local check: entries read
   `version: 0.0.0-use.local`, `linkType: soft`, no manifest checksum) → CI version bumps do
   **not** dirty `yarn.lock`; no lockfile-repair step needed in the release workflow.
10. **semantic-release 0.x semantics** (official FAQ): from tag `0.1.0` → `fix:`/`perf:` = 0.1.1,
    `feat:` = 0.2.0, `BREAKING CHANGE` = **1.0.0** (semrel explicitly refuses 0.x breaking→minor;
    fine — `^0.1.x` consumers are protected either way). Default `tagFormat` is `v${version}`;
    MSR uses per-project tags — its default **`${name}@${version}`** (no `v`) is kept
    (e.g. `@rae-hill/scratch@0.1.0`; confirmed in dry-run).
11. **RsLib** `@rslib/core` 1.x (GA Sep 2026; Node ≥ 20.19/22.12): bundleless ESM via
    `lib: [{ format: 'esm', bundle: false, dts: true }]`; output `dist/` by default; auto-external
    deps; `rslib build --watch`. v1.1.0 added `lib[].exports` with `source: true` that writes our
    exact dual-manifest pattern automatically (`exports → src`, `publishConfig.exports → dist`);
    docs explicitly say to publish with `yarn npm publish`/`pnpm publish`. If the installed
    1.0.x lacks it, hand-write the manifest fields (static anyway). RsLib's release-management
    guide is pnpm-centric — we ignore it except for its validation-plugin advice:
    `rsbuild-plugin-publint` + `rsbuild-plugin-arethetypeswrong` (enabled when `CI=true`).
12. **TypeDoc** is at 0.28.x (supports TS ≥ 5.9 since 0.28.18's TS 6.0 support; no 0.29 exists);
    **no native markdown output** — requires `typedoc-plugin-markdown` (peer `typedoc ~0.28`).
    TSDoc comment style is natively supported.
13. **RsPress v2** = `@rspress/core` (v1 `rspress` package deprecated); built-in **`multiVersion`**
    docs (`docs/v0.1/`, `docs/v0.2/` trees + version dropdown) — matches "organized by minor
    release version" exactly; default outDir `doc_build`. **`@rspress/plugin-typedoc` is
    RsPress-v1-only (peer `rspress ^1.0.0`) and regenerates MD at site build** — conflicts with
    committed versioned MD on both counts → **not used**; standalone TypeDoc generates the MD.
14. **Rspack bindings** (`@rspack/binding-linux-x64-gnu` etc.) are prebuilt N-API
    `optionalDependencies` — no node-gyp; clean under yarn 4 `nodeLinker: node-modules` and CI
    `yarn install --mode=skip-build`.
15. **GITHUB_TOKEN pushes never trigger workflows** → semantic-release's release-commit pushback to
    `main` cannot recurse (its default `[skip ci]` message is belt-and-braces).
16. **`npmMinimalAgeGate: "5d"`** (`.yarnrc.yml`): several needed packages are days old at time of
    writing (`semantic-release@26.0.1` Nov 16, `@rslib/core@1.0.7` ~4d, `@rspress/core@2.1.4`
    ~hours). At install time, pin the newest versions older than 5 days (e.g. semantic-release 25.x,
    previous rslib/rspress patches) or install after they age.
17. **Node bumped (Nov 20, 2026)**: all flake inputs updated (`nix flake update`); devshell node is
    now v26.13.1 (was 26.11.1) and `.nvmrc` matches — semantic-release 26's `>=26.13` engine is
    satisfied everywhere; it stays age-gate-blocked until Nov 21, so initial pin is 25.x with a
    trivial later upgrade. npm in devshell: 11.20.0 (≥11.5.1 trusted-publishing requirement ✓).

## Architecture

### Library layout (template = `lib/scratch`)

```
lib/scratch/
├── src/index.ts              # throwaway functions with TSDoc comments
├── test/index.test.ts        # vitest
├── docs/                     # COMMITTED: TypeDoc markdown, per minor version
│   └── v0.1/**/*.md          #   (+ _meta.json per version for RsPress sidebars)
├── rspress.config.ts         # RsPress v2 site: root 'docs', multiVersion (versions scanned
│                             #   from docs/ dir listing), outDir 'doc_build'
├── dist/                     # GITIGNORED: RsLib output (js + d.ts + maps)
├── doc_build/                # GITIGNORED: RsPress HTML output
├── package.json              # dual-manifest (see below)
├── rslib.config.ts           # lib:[{format:'esm',bundle:false,dts:true,exports:{source:true}}],
│                             #   publint + arethetypeswrong plugins on every build
├── typedoc.json              # entryPoints src, plugin typedoc-plugin-markdown
├── tsconfig.json / tsconfig.src.json / tsconfig.test.json   # repo pattern (typecheck)
├── vitest.config.ts          # merges ../../vitest.shared.ts
├── README.md
└── LICENSE
scripts/typedoc-versioned.mjs # shared: reads lib pkg version → runs typedoc --out docs/v<major>.<minor>
```

Note: no `tsconfig.build.json`/tsc emit — RsLib (with `dts: true`) produces `dist/`, and the root
`tsconfig.build.json` (which drives tsc-emit for the Nix-packaged apps) is NOT touched: libs
typecheck via their own solution tsconfig through the repo-wide `yarn typecheck`
(`workspaces foreach`), and the release workflow gates on it directly.

### package.json (the dual-manifest pattern)

```jsonc
{
  "name": "@rae-hill/scratch",
  "version": "0.1.0",
  "type": "module",
  "license": "MIT",
  "sideEffects": false,
  "description": "Throwaway proof-of-concept library for the lib/* publishing pipeline",
  "repository": {
    "url": "git+https://github.com/rae-hill/homelab.git",   // exact match required for provenance verification
    "directory": "lib/scratch"
  },
  "files": ["dist"],                                        // README/LICENSE always included by berry
  // exports + publishConfig.exports below are GENERATED/kept in sync by RsLib's
  // lib[].exports { source: true } feature (rslib.rs/config/lib/exports) — shown here as the
  // resulting shape; don't hand-edit them once generate-exports is wired.
  "exports": { "." : { "import": "./src/index.ts" } },      // workspace dev DX (repo convention)
  "publishConfig": {
    "access": "public",
    "provenance": true,
    "exports": { ".": { "types": "./dist/index.d.ts", "import": "./dist/index.js" } }
    // ^ exact filenames must match RsLib output (autoExtension behavior verified at build time)
  },
  "engines": { "node": ">=22.12" },
  "scripts": {
    "build": "rslib build",
    "build:watch": "rslib build --watch",
    "docs": "node ../../scripts/typedoc-versioned.mjs",
    "docs:site": "rspress build",
    "docs:dev": "rspress dev",
    "lint": "eslint src",
    "typecheck": "tsc -b tsconfig.json --noEmit",
    "test": "vitest run",
    "test:staged": "vitest related --run"
  },
  "devDependencies": {
    "@rslib/core": "<age-gate-legal version>",
    "@rspress/core": "<age-gate-legal version>",
    "typedoc": "~0.28.20",
    "typedoc-plugin-markdown": "<latest 4.x/10.x peer-compatible>",
    "rsbuild-plugin-publint": "...",
    "rsbuild-plugin-arethetypeswrong": "...",
    "vitest": "^5.x", "vite": "^8.3.5", "@types/node": "^24", "madge": "^8"
  }
}
```

Lib→lib dependencies (future): `"@rae-hill/other": "workspace:^"` — yarn links the local workspace
for dev and rewrites to `^<version>` at publish (fact 4). **Never plain semver ranges for
in-repo libs** (they can silently flip to registry resolution after a bump).

### Consuming libs from `packages/*`

Add `"@rae-hill/scratch": "workspace:*"` to the app's deps; `import { ... } from "@rae-hill/scratch"`
resolves to TS source via `exports` — zero build step in development, works in vitest/vite/astro/
rolldown/tsc (same as existing `shared`/`homelab-data` usage). Add the lib to the consumer's
tsconfig `references` where the repo pattern requires it.

### Release pipeline

Root `release.config.js` consumed by `@anolilab/multi-semantic-release` (one semantic-release per
non-private workspace, cwd = package dir, path-scoped commit analysis, per-project tags).

- Branch: `main`. Tag format: MSR default `${name}@${version}` → `@rae-hill/scratch@0.1.0` (no `v`).
- `packages/*` are excluded by marking every app/internal package `"private": true` (semrel skips
  private packages; also blocks accidental publishes). Vestigial `publishConfig`/`<PLACEHOLDER>`
  `repository` blocks removed in the same pass.
- Plugin order (prepare steps run in order, then publish, then success):

| # | Plugin | Config | Role |
| --- | --- | --- | --- |
| 1 | `@semantic-release/commit-analyzer` | default conventional | feat→minor, fix/perf→patch, BREAKING→major; only commits touching the lib's path (MSR filtering) |
| 2 | `@semantic-release/release-notes-generator` | — | GitHub Release notes |
| 3 | `@semantic-release/changelog` | — | per-lib `CHANGELOG.md` |
| 4 | `@semantic-release/npm` | `npmPublish: false` | **version bump only** (prepare edits `package.json`) |
| 5 | `@semantic-release/exec` | `prepareCmd: "yarn build && yarn docs"` | rebuild `dist/` **after** the bump; regenerate versioned docs for the new minor |
| 6 | `@semantic-release/git` | assets: `package.json`, `CHANGELOG.md`, `docs/` | release commit `chore(release): … [skip ci]` pushed to main (inert, no recursion) |
| 7 | `@semantic-release/exec` | `publishCmd: "yarn npm publish --access public --tolerate-republish"` | OIDC + provenance + publishConfig swap + workspace rewrite, all in one (publishConfig.provenance/access also set, flags are belt-and-braces) |
| 8 | `@semantic-release/github` | — | GitHub Release + issue/PR comments |

(Same `exec` plugin instance carries both prepareCmd and publishCmd; shown twice for lifecycle
clarity.) First release behavior: no tag + feat commit → 1.0.0, so bootstrap pins 0.1.0 via a tag
(runbook below). Non-conventional commits → no release.

Root devDeps (exact-pinned, age-gate-legal): `semantic-release`,
`@anolilab/multi-semantic-release`, `@semantic-release/{commit-analyzer,release-notes-generator,changelog,npm,exec,git,github}`.
Root script: `"release": "multi-semantic-release"`.

### Workflow `.github/workflows/release.yml`

```yaml
name: Release
on:
  push:
    branches: [main]
    paths: ["lib/**", "scripts/typedoc-versioned.mjs", "release.config.js",
            ".github/workflows/release.yml", ".github/actions/setup/action.yml"]
concurrency: { group: release, cancel-in-progress: false }
permissions:
  contents: write        # tags, release commits, GitHub Releases
  issues: write          # release comments
  pull-requests: write   # release comments
  id-token: write        # OIDC: npm trusted publishing + sigstore provenance
jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: ./.github/actions/setup        # extended with fetch-depth input; pass 0 (full history + tags)
        with: { fetch-depth: 0 }
      - run: yarn workspaces foreach --from '{@rae-hill/*}' -pt run typecheck   # gate
      - run: yarn workspaces foreach --from '{@rae-hill/*}' -pt run lint        # gate
      - run: yarn workspaces foreach --from '{@rae-hill/*}' -pt run test        # gate
      - run: yarn release
```

No `NPM_TOKEN`, no `NPM_CONFIG_PROVENANCE` (yarn handles provenance via `publishConfig`), no
`registry-url`/`.npmrc` gymnastics. `foreach --from` pattern syntax verified at implementation
(fallback: path glob `--from './lib/*'`). Self-contained gates so broken code can't publish even
though the main CI runs in parallel.

### Docs pipeline details

- **Generation**: `scripts/typedoc-versioned.mjs <lib-dir>` (shared): reads the lib's
  `package.json` version → runs its `typedoc.json` with output forced to
  `docs/v<major>.<minor>/` (TypeDoc markdown via `typedoc-plugin-markdown`; TSDoc comments
  natively). Regenerates the *current minor's* folder; prior minors stay as history.
- **Site**: per-lib `rspress.config.ts` (`@rspress/core` v2): `root: 'docs'`,
  `outDir: 'doc_build'` (gitignored), `multiVersion` with the versions array **scanned from the
  `docs/` directory listing at config time** (zero maintenance when a new minor folder appears),
  default = highest version. `_meta.json` per version folder controls sidebars.
- **Pre-commit** (lint-staged.config.js addition): when staged files touch
  `lib/<name>/{src,test,package.json,typedoc.json,rslib.config.ts}` → run
  `yarn workspace @rae-hill/<name> build` (RsLib build incl. **publint + arethetypeswrong**
  checks — publish-readiness is validated on every commit that touches a lib) and
  `yarn workspace @rae-hill/<name> docs`, then `git add lib/<name>/docs` so regenerated MD rides
  along with the commit. (Agent commits use `--no-verify` per AGENTS.md → the creating-libs skill
  instructs agents to run build + docs manually before committing.)
- **Release-time**: exec `prepareCmd` runs `yarn docs` after the version bump → when a release
  crosses into a new minor (0.1.x → 0.2.0), `docs/v0.2/` is created and committed by
  `@semantic-release/git`; the committed MD always matches the released API.
- **HTML** is never committed; `doc_build/` is gitignored. `yarn docs:dev` previews locally;
  static output can later be served from the public server (out of scope here).

### Bootstrap runbook (owner, one time — two paths)

Goal: `@rae-hill/scratch@0.1.0` on npm + Trusted Publishing configured, without ever creating a
long-lived token. **Owner selected Path 1**; Path 2 kept as fallback.

- **Path 1 (preferred, zero-token — try first)**: npm allows scope-level Trusted Publisher config
  *before* the package exists (research fact 7; verify in UI: npmjs.com → `@rae-hill` scope →
  Settings → Trusted Publisher → add: owner `rae-hill`, repo `homelab`, workflow `release.yml`,
  environment blank). Then bootstrap the version baseline in git: after the scaffold lands, tag
  the pre-feature commit `@rae-hill/scratch@0.0.0` and push a `feat(scratch): …` commit → CI
  computes 0.0.0 + feat = **0.1.0** and publishes it via OIDC with provenance. Must succeed within
  **2 days** of TP creation or the config expires (re-create if so).
- **Path 2 (fallback, matches owner's plan)**: build locally (`yarn build` in `lib/scratch`),
  `npm login` + `npm publish --access public` (from `lib/scratch`; note npm won't apply the
  publishConfig.exports swap — for a one-off manual publish either use
  `yarn npm publish` with a short-lived granular token instead, or accept and fix), then
  `git tag '@rae-hill/scratch@0.1.0'` on that commit + push tag, then configure TP as above.
  First version has no provenance; 0.1.1 onward does.
- After first success: optionally enable "require 2FA / disallow tokens" on the package.
- If scope-level TP turns out not to cover new packages, add per-package TP entries as libs are
  created (skill will include the checklist item).

## Risks & fallbacks

- **MSR fork churn** ("janky" self-description): exact-pin everything. Fallbacks: (a) pin the
  semrel major the fork supports, (b) per-lib plain semantic-release with scope-gated
  `releaseRules`, (c) `zx-bulk-release` (drops the semrel plugin model).
- **RsLib `exports` automation needs @rslib/core ≥1.1.0** (research saw 1.0.7 as latest — verify
  against the registry): if no age-gate-legal ≥1.1.0 exists yet, hand-write the manifest fields
  once (they're static) and enable `lib[].exports { source: true }` as soon as one ages in; the
  generated shape is identical either way.
- **RsLib output extensions** (`autoExtension` behavior for `.js` vs `.mjs`, dts `.d.ts` vs
  `.d.mts`) must match `publishConfig.exports` exactly — publint/attw plugins + pack inspection
  catch drift.
- **TypeDoc pinned to 0.28.x** (frozen line): acceptable; typedoc-plugin-markdown peer is
  `~0.28`. If TS 6.x ever lands in-repo, recheck support.
- **Trusted-publisher bootstrap uncertainty** (scope-level config for not-yet-existing packages is
  documented but unproven here): Path 2 fallback is ready.
- **@semantic-release/npm local verify without tokens** may block `--dry-run` outside CI:
  documented workaround (per-lib `yarn npm publish --dry-run`); last resort is swapping the bump to
  an exec `npm pkg set version=${nextRelease.version}` prepareCmd.
- **Pre-commit docs generation cost**: TypeDoc on a small lib ≈ 1–2s; if it ever gets slow, gate
  the hook to only libs whose `src/` changed (already the design) and keep RsPress HTML out of the
  hook (it is — HTML is on-demand only).
- **Age gate** may block day-0 versions of everything above → pin one patch back; revisit later.
